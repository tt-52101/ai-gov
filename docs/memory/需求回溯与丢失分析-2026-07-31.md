## 五、版本演进与价值稀释路径

```text
原始讨论（505行）
  愿景 ✔ + 功能 ✔ + 价值 ✔ + 预留设计 ✔
      ↓ 价值叙事开始淡化
v1.0.0（558行）
  功能 ✔ + 规则 ✔ + 边界 ✔
      ↓ + TokenHub/AxonHub 选型 + 策略矩阵 + 架构原则
v1.0.1（688行）
  功能 ✔ + 规则 ✔ + 边界 ✔ + 架构原则 ✔
      ↓ + 预算帽分码修正（结构被压缩）
v1.0.2（487行）
  功能 ✔ + 错误码 ✔（功能表被压缩为摘要）
      ↓ + ModelGrant + 错误码全表（第 9 章被一行替代）
v2.0.0（672行）
  功能 ✔ + ModelGrant ✔ + 错误码 ✔（功能表丢失）
      ↓ 恢复第 9 章 + 门禁/交付物（但未回填原始价值）
v2.0.1（852行）
  功能 ✔ + 验收 ✔ + 门禁 ✔
  ❌ 架构原则 ✗ + 非功能验收 ✗ + 预留设计 ✗ + 价值叙事 ✗
```

**核心病灶：** 每次迭代都是"技术收敛"，但缺少"价值回填"——回到最原始的讨论，确认用户最初要解决的问题、为什么这样设计、价值在哪里。
