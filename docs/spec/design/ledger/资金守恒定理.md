# 划拨守恒事务实现详述

目标：一次划拨在**同一数据库事务**内完成「源账户减少、目标账户增加、金额相等、流水可追溯」；失败则全部回滚；支持幂等，禁止无流水改余额。

---

## 1. 业务语义（与 PRD 对齐）

| 项 | 规则 |
|----|------|
| 守恒 | `source.balance -= amount` 且 `target.balance += amount`，`amount > 0`，同一事务 |
| 通道 | 默认仅 parent 上级→下级，或 sponsors 出资方→被出资方；否则查白名单 |
| 权限 | 操作者对**源账户**具备 fund.`allocate` |
| 状态 | 源/目标账户非清算中、非关闭 |
| 余额 | 源 `balance - frozen >= amount`（划拨动用的是**可用余额**，不动冻结） |
| 幂等 | 同一 `Idempotency-Key` 不产生第二次记账 |
| 审计 | 至少两笔 ledger（或一笔带双边语义 + 两账户 balance_after） |

---

## 2. 推荐账户模型与锁

```text
accounts:
  balance, frozen, version   -- version 乐观锁
  status                     -- active | liquidating_* | closed
```

**可用余额：** `available = balance - frozen`  
划拨只减少 `balance`，不增加源的 `frozen`。

**并发策略（二选一，商用推荐 A）：**

- **A. 事务内 `SELECT ... FOR UPDATE`** 按稳定顺序锁两行（避免死锁）  
- **B. 乐观锁 `UPDATE ... WHERE version = ?`**，冲突则重试有限次  

下文以 **FOR UPDATE + 有序加锁** 为主（实现简单、守恒直观）。

---

## 3. 通道校验（事务外或事务内均可，建议事务前）

```text
function CanAllocate(fromPartyID, toPartyID) -> bool:
  if exists edge(parent, from -> to) and from is ancestor of to: return true
  if exists edge(sponsors, from -> to): return true
  if exists allocate_whitelist(from, to): return true
  return false
```

组织树 `parent`：仅允许**祖先 → 后代**，禁止下级向上、禁止无边平级。  
`sponsors`：仅边的方向出资方 → 被出资方。

---

## 4. 幂等与请求指纹

```text
scope = "allocate"
key   = Idempotency-Key header
hash  = SHA256(canonical_json({from_account_id, to_account_id, amount, currency?}))
```

流程：

1. 无 Key → 可拒绝（资金写强制）或按项目策略。  
2. `INSERT idempotency_records (scope, actor, key, hash, status=started)`  
   - 冲突：读已有行 → succeeded 则返回缓存结果；started 则 409；hash 不同则 409 异参。  
3. 业务成功后再 `UPDATE status=succeeded, response_body, resource_ref`。  
4. 业务失败：`status=failed` 并缓存错误语义（是否允许同键重试由策略决定，默认资金失败可同键重试需产品定；更稳妥是失败也缓存，换 Key 重试）。

## 5. 核心事务伪代码（PostgreSQL + Go 风格）

```go
type AllocateCmd struct {
    FromAccountID int64
    ToAccountID   int64
    Amount        decimal.Decimal // > 0
    ActorID       string
    IdemKey       string
    RequestHash   string
    Remark        string
}

func (s *FundService) Allocate(ctx context.Context, cmd AllocateCmd) (*AllocateResult, error) {
    if cmd.Amount.LessThanOrEqual(decimal.Zero) {
        return nil, errInvalidAmount
    }
    if cmd.FromAccountID == cmd.ToAccountID {
        return nil, errSameAccount
    }

    // 1) 幂等抢占（可先短事务，或与主事务合并）
    claimed, prev, err := s.idem.Claim(ctx, "allocate", cmd.ActorID, cmd.IdemKey, cmd.RequestHash)
    if err != nil { return nil, err }
    if !claimed {
        return prev.AsAllocateResult() // 重放
    }

    // 2) 授权与通道（读模型，尽量事务外）
    if err := s.authz.Require(ctx, cmd.ActorID, "fund", "allocate", cmd.FromAccountID); err != nil {
        s.idem.Fail(ctx, ...)
        return nil, err // AUTHZ_DENIED
    }
    fromAcc, toAcc, err := s.loadAccountsMeta(ctx, cmd.FromAccountID, cmd.ToAccountID)
    if err != nil { ... }
    if !s.channel.CanAllocate(fromAcc.PartyID, toAcc.PartyID) {
        s.idem.Fail(ctx, ...)
        return nil, errChannelDenied
    }

    // 3) 守恒事务
    var result *AllocateResult
    err = s.db.Transaction(func(tx *sql.Tx) error {
        // 3.1 有序加锁，防止死锁：始终先锁 id 较小的账户
        id1, id2 := cmd.FromAccountID, cmd.ToAccountID
        if id1 > id2 { id1, id2 = id2, id1 }

        a1, err := lockAccount(tx, id1) // SELECT * FROM accounts WHERE id=$1 FOR UPDATE
        if err != nil { return err }
        a2, err := lockAccount(tx, id2)
        if err != nil { return err }

        from, to := a1, a2
        if from.ID != cmd.FromAccountID {
            from, to = a2, a1
        }

        // 3.2 状态
        if from.Status != "active" || to.Status != "active" {
            return errAccountNotActive // -> ACCOUNT_FROZEN_OR_CLOSED
        }

        // 3.3 可用余额
        available := from.Balance.Sub(from.Frozen)
        if available.LessThan(cmd.Amount) {
            return errInsufficientBalance // 划拨场景可用专用码或复用 INSUFFICIENT_BALANCE
        }

        // 3.4 账面更新（守恒）
        newFromBal := from.Balance.Sub(cmd.Amount)
        newToBal   := to.Balance.Add(cmd.Amount)

        if err := updateBalance(tx, from.ID, newFromBal, from.Frozen, from.Version); err != nil {
            return err
        }
        if err := updateBalance(tx, to.ID, newToBal, to.Frozen, to.Version); err != nil {
            return err
        }

        // 3.5 流水（建议两笔，便于单账户对账）
        outID, err := insertLedger(tx, Ledger{
            AccountID: from.ID, PeerAccountID: &to.ID,
            Type: "allocate_out", Amount: cmd.Amount.Neg(), // 或 Amount 为正、Type 区分方向
            BalanceAfter: newFromBal, FrozenAfter: from.Frozen,
            IdempotencyKey: cmd.IdemKey, OperatorID: cmd.ActorID, Remark: cmd.Remark,
        })
        if err != nil { return err }

        inID, err := insertLedger(tx, Ledger{
            AccountID: to.ID, PeerAccountID: &from.ID,
            Type: "allocate_in", Amount: cmd.Amount,
            BalanceAfter: newToBal, FrozenAfter: to.Frozen,
            IdempotencyKey: cmd.IdemKey, OperatorID: cmd.ActorID, Remark: cmd.Remark,
        })
        if err != nil { return err }

        // 可选：同一 batch_id 串起两笔
        result = &AllocateResult{
            FromBalance: newFromBal, ToBalance: newToBal,
            LedgerOutID: outID, LedgerInID: inID,
        }
        return nil
    })

    if err != nil {
        s.idem.Fail(ctx, "allocate", cmd.ActorID, cmd.IdemKey, err)
        return nil, err
    }

    s.idem.Complete(ctx, "allocate", cmd.ActorID, cmd.IdemKey, result)
    // 配置/操作审计异步或同库另一表
    return result, nil
}
```

**流水金额符号约定（二选一，全项目统一）：**

- 方案 1：`amount` 恒为正，`type` 区分 `allocate_out` / `allocate_in`。  
- 方案 2：以账户视角带符号（出为负、入为正）。  

推荐方案 1，报表更直观。

## 6. SQL 示意

```sql
BEGIN;

-- 有序锁
SELECT id, balance, frozen, version, status, party_id
FROM accounts WHERE id IN ($from, $to)
ORDER BY id
FOR UPDATE;

-- 应用层校验 available、status、通道结果

UPDATE accounts SET balance = balance - $amount, version = version + 1, updated_at = now()
WHERE id = $from AND status = 'active';

UPDATE accounts SET balance = balance + $amount, version = version + 1, updated_at = now()
WHERE id = $to AND status = 'active';

INSERT INTO ledgers (account_id, peer_account_id, type, amount, balance_after, frozen_after, idempotency_key, operator_id, remark)
VALUES
  ($from, $to, 'allocate_out', $amount, $from_bal_after, $from_frozen, $idem, $actor, $remark),
  ($to, $from, 'allocate_in',  $amount, $to_bal_after,   $to_frozen,   $idem, $actor, $remark);

COMMIT;
```

若用乐观锁，则：

```sql
UPDATE accounts SET balance = $new_bal, version = version + 1
WHERE id = $id AND version = $old_version;
-- rowcount=0 → 重试整个事务
```

## 7. 不变式（事务提交后必须成立）

设划拨金额为 \(A\)：

\[
\Delta balance_{from} = -A,\quad \Delta balance_{to} = +A,\quad \Delta balance_{from}+\Delta balance_{to}=0
\]

- 全系统账户 `balance` 之和在仅发生划拨时不变（冻结/结算另算）。  
- 任意账户：`balance >= 0` 且 `frozen >= 0` 且 `balance >= frozen`（若业务禁止透支）。  
- 每笔余额变更可在 `ledgers` 找到对应记录。

可用定时对账作业：抽查 `sum(allocate_out)` 与 `sum(allocate_in)` 按 `idempotency_key` 或时间窗相等。

## 8. 与清算、冻结的边界

| 操作 | 是否走 Allocate | 说明 |
|------|-----------------|------|
| 日常划拨 | 是 | 本文 |
| 清算回流 | **独立命令** | 状态机 + 可突破「仅向下」，但仍等额双边 + 流水 + fund 授权 |
| 预扣冻结 | 否 | `balance` 不变，`frozen += x` |
| 结算 | 否 | `frozen -= x`，`balance -= sell`（实扣） |

清算**不要**复用未校验状态的 Allocate，以免跳过 `liquidating_*` 约束。

## 9. 错误映射

| 条件 | code 建议 |
|------|-----------|
| 权限不足 | `AUTHZ_DENIED` |
| 通道不允许 | `ALLOCATE_CHANNEL_DENIED`（可归入 AUTHZ 或独立） |
| 可用余额不足 | `INSUFFICIENT_BALANCE` |
| 账户非 active | `ACCOUNT_FROZEN_OR_CLOSED` |
| 同键异参 | `IDEMPOTENCY_CONFLICT` |
| amount ≤ 0 或同户 | 400 参数错误 |

## 10. 测试清单（必须自动化）

1. **守恒：** 划拨前后 `from+to` 余额之和不变；与流水一致。  
2. **并发：** 两笔划拨抢同一源账户，终态余额正确、无超扣。  
3. **幂等：** 同 Key 连点两次，仅一笔账；第二次响应一致。  
4. **异参同键：** 改 amount 再提交 → CONFLICT。  
5. **通道：** 下级向上失败；无边平级失败；sponsors 反向失败；白名单成功。  
6. **冻结并存：** 源有 frozen 时，只能划 `balance-frozen`。  
7. **崩溃恢复：** 事务中断无半边入账；幂等 started 超时后的处理策略符合设计。

---

## 11. 实现要点小结

1. **一事务、两账户有序锁、等额加减、双边流水。**  
2. **通道 + 授权在记账前失败并回滚（或根本不进事务）。**  
3. **幂等键覆盖「谁、从哪到哪、多少」。**  
4. **划拨只碰 available，不碰冻结语义。**  
5. **清算单独状态机，不借用裸 Allocate。**  

按上述实现即可满足 PRD 中的资金流转定理与 FUN-04/FUN-05，并与预算帽、调用预扣路径隔离清晰。
