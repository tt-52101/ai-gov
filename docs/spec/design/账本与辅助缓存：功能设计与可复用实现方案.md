# 账本与辅助缓存：功能设计与可复用实现方案

**决策固化**

| 层级 | 技术 | 职责 |
|------|------|------|
| 权威账本 + 热路径资金 | **SQL 库本地事务**（PostgreSQL 生产 / **SQLite 最小化单机**） | 余额、冻结、流水、幂等、划拨守恒 |
| 可选加速 | **Redis**（可关） | 鉴权缓存、限流、冻结到期提示；**不记账** |

融合架构（TokenHub）本身支持 SQLite 单机与 PG 多实例：资金模块必须走**同一套领域接口 + 可切换 Store**，禁止写死只连 Redis 或只连 PG。

---

## 1. 目标与约束

### 1.1 功能目标

- 划拨守恒、预扣冻结、结算、超时解冻、清算状态机、预算帽、幂等写  
- 单机 SQLite 可完整演示财务闭环  
- 多实例仅推荐 **PostgreSQL** 作为账本库（多实例共享）  
- Redis 全关时系统仍正确（仅可能少缓存、少分布式限流）

### 1.2 硬约束

1. 任何余额变更必须有 ledger（或 freeze 状态机可追溯）。  
2. 划拨：单事务内两账户等额变化。  
3. 不把上游 HTTP 包进分布式事务。  
4. SQLite 与 PG 行为差异集中在 **Adapter 锁与重试**，领域规则一致。

## 2. 逻辑架构（可复用）

```text
                    ┌─────────────────────────────────────┐
                    │  Fund / Freeze / Allocate / Budget   │  领域服务（无 SQL 方言）
                    └─────────────────┬───────────────────┘
                                      │ FundStore 接口
                    ┌─────────────────┴───────────────────┐
                    │     SQL FundStore (GORM/database/sql) │
                    │  事务、FOR UPDATE 或 SQLite 忙重试      │
                    └─────────────────┬───────────────────┘
                                      │
              ┌───────────────────────┼───────────────────────┐
              ▼                       ▼                       ▼
        SQLite (单机最小化)      PostgreSQL (多实例/商用)    只读副本(可选)
              
              Redis (可选) ──► AuthCache / RateLimit / FreezeHintZSet
                              失效时降级：直读 SQL，不阻断扣费
```

TokenHub 现有 `store` 可扩展：`FundStore` 与现有 GORM DB 共用同一 `*gorm.DB` / 同一 DSN 策略。

## 3. 部署模式矩阵

| 模式 | 账本库 | Redis | 说明 |
|------|--------|-------|------|
| 最小化试用 | SQLite 文件 | 关 | 单进程；财务闭环可演示 |
| 单机生产 | SQLite 或 PG | 可选 | 并发高建议迁 PG |
| 多实例商用 | **必须 PostgreSQL** | 可选 | 多副本共享账本；禁止多实例共享同一 SQLite 文件做写 |
| 仅限流增强 | 任意 SQL 账本 | 开 | Redis 挂不影响对账 |

**启动校验：**

- `instances > 1` 且 driver=sqlite → **拒绝启动**或强制只读告警。  
- Redis ping 失败 → 日志告警，资金路径继续（无缓存）。

## 4. 领域接口（与库无关，供融合复用）

```go
package fund

type Store interface {
    WithTx(ctx context.Context, fn func(tx Tx) error) error
}

type Tx interface {
    // 账户
    GetAccountForUpdate(ctx context.Context, id int64) (*Account, error)
    UpdateAccountBalances(ctx context.Context, id int64, balance, frozen decimal.Decimal, version int64) error
    // 流水与冻结
    InsertLedger(ctx context.Context, e Ledger) (int64, error)
    InsertFreeze(ctx context.Context, f Freeze) error
    GetFreezeForUpdate(ctx context.Context, freezeID string) (*Freeze, error)
    UpdateFreezeStatus(ctx context.Context, freezeID, status string) error
    // 幂等
    ClaimIdempotency(ctx context.Context, rec IdemRecord) (claimed bool, existing *IdemRecord, err error)
    CompleteIdempotency(ctx context.Context, scope, actor, key string, status string, code int, body []byte, ref string) error
    // 扫描（超时解冻）
    ListExpiredOpenFreezes(ctx context.Context, limit int) ([]Freeze, error)
}

type Service struct {
    Store Store
    // Channel / Authz 等
}
```

业务方法：`Allocate`、`Freeze`、`Settle`、`UnfreezeTimeout`、`Liquidate` 只依赖 `Store`，不依赖 Redis。

## 5. SQL 账本实现要点（SQLite + PostgreSQL）

### 5.1 表结构

沿用已给出的 `accounts / ledgers / freezes / idempotency_records / parties...`。  
SQLite 注意：

- 无 `BIGSERIAL` → `INTEGER PRIMARY KEY AUTOINCREMENT`  
- `NUMERIC` 可用 `TEXT` 存十进制字符串或 `REAL`（**财务推荐 TEXT + 应用层 decimal**）  
- JSON：SQLite 3.38+ JSON1，或 TEXT 存 JSON  

迁移工具按 driver 生成两套方言或使用 GORM AutoMigrate + 手工校验。

### 5.2 事务与锁

**PostgreSQL：**

```sql
SELECT * FROM accounts WHERE id IN ($1,$2) ORDER BY id FOR UPDATE;
```

**SQLite：**

- 默认文件锁；写事务串行。  
- `BEGIN IMMEDIATE` 尽早抢写锁，减少 `SQLITE_BUSY`。  
- 忙时：应用层指数退避重试（如 5～10 次）。  
- **不必**模拟 FOR UPDATE；单写事务内读到的即当前快照。

```go
func (s *SQLStore) WithTx(ctx context.Context, fn func(Tx) error) error {
    return retryBusy(func() error {
        return s.db.Transaction(func(tx *gorm.DB) error {
            if s.driver == "sqlite" {
                tx.Exec("BEGIN IMMEDIATE") // 若外层已 transaction，按 driver 文档处理
            }
            return fn(&sqlTx{tx: tx, driver: s.driver})
        })
    })
}
```

### 5.3 划拨守恒（两库同一领域逻辑）

```text
WithTx:
  锁/读 from、to（PG: FOR UPDATE 有序；SQLite: 事务内读）
  校验 status、available >= amount、通道（通道可在事务外）
  balance_from -= amount; balance_to += amount
  InsertLedger out + in
Commit
```

### 5.4 冻结 / 结算 / 超时

| 操作 | SQL 事务内 |
|------|------------|
| Freeze | available 足够；frozen+=a；insert freezes(open, expires_at) |
| Settle | freeze 仍 open；frozen-=a；balance-=sell；freeze=settled；ledger |
| Timeout | 抢占 open 且过期 → frozen-=a；status=timeout_released；ledger |

多实例 TTL：只靠 **PG 上多个 worker `UPDATE ... WHERE status='open' AND expires_at<? RETURNING`** 抢占；SQLite 单进程一个 worker 即可。

### 5.5 幂等

`UNIQUE(scope, actor_id, idempotency_key)` 两库都支持。  
Claim：`INSERT` 成功=claimed；冲突则 `SELECT` 判断重放/异参。

## 6. Redis 辅助设计（可关、可复用）

### 6.1 模块划分

```go
package auxredis

type AuthCache interface {
    GetKeyMeta(ctx, keyHash string) (accountID int64, userID int64, status string, ok bool)
    SetKeyMeta(...)
    InvalidateKey(...)
}

type RateLimiter interface {
    Allow(ctx, bucket string, limit int, window time.Duration) (bool, error)
}

type FreezeHint interface {
    Schedule(ctx, freezeID string, expiresAt time.Time) error
    PopDue(ctx, now time.Time, limit int) ([]string, error)
}
```

配置：`REDIS_URL` 为空 → 全部 Noop 实现。

### 6.2 鉴权缓存

- 命中：减少 SQL 查 Key。  
- 禁人/吊销/改绑账户：**必须 Invalidate**；TTL 建议 30～60s 兜底。  
- **扣费前余额与冻结只信 SQL**，不信 Redis 里的 balance。

### 6.3 限流

- 按 Key、账号、IP、模型维度；超限返回 `RATE_LIMITED`。  
- Redis 宕机：策略可选 fail-open（放行）或 fail-closed；**默认 fail-open 并打点**，避免拖死网关；账本仍由 SQL 保护。

### 6.4 冻结到期提示（非权威）

```text
ZADD freeze_hints <expires_at_unix> <freeze_id>
Worker: ZRANGEBYSCORE → 对每个 id 调 FundService.UnfreezeTimeout
       UnfreezeTimeout 内部仍 SELECT freeze FOR UPDATE / 条件更新 SQL
```

Redis 丢 ZSET → 最坏等到 SQL 全表/索引扫描任务（按 `expires_at` 索引），**资金不错**。

## 7. 数据面管道中的挂载点（融合 TokenHub）

```text
Auth:
  Key 校验 → (可选 AuthCache) → 未命中查 SQL → 回填缓存
RateLimit:  (可选) 超限则返回
ModelGrant / PriceCap / BudgetCap:  读 SQL
Freeze:     仅 SQL 事务
Route + Upstream HTTP
Settle:     仅 SQL 事务
```

控制面 `Allocate` / `Liquidate`：仅 SQL + 幂等表；成功后可 `AuthCache.Invalidate` 相关 Key（若有）。

## 9. SQLite 最小化部署专项

| 项 | 做法 |
|----|------|
| 文件 | 与 TokenHub 同目录或配置路径；注意备份拷贝 db 文件 |
| 并发 | 单进程写；WAL mode：`PRAGMA journal_mode=WAL` |
| 小数 | 金额用字符串 decimal，避免 REAL 误差 |
| 迁移 | 启动时 AutoMigrate 资金表 |
| 演示 | 关 Redis 跑通：建 Party → 划拨 → Key 调用 → 冻结结算 → 清算 |
| 升级路径 | 导出/逻辑迁移到 PG：同 schema 导出 ledger 与 account |

## 12. 小结

| 问题 | 答案 |
|------|------|
| 权威账本是谁 | **当前 SQL 库（SQLite 或 PostgreSQL）本地事务** |
| Redis 是什么 | 可选缓存/限流/到期提示，**可整体关闭** |
| 最小化部署 | SQLite + 关 Redis，财务闭环可完整跑 |
| 多实例商用 | **PostgreSQL 共享账本**；Redis 仍可选 |
| 2PC | 不实现 |
| 复用方式 | `FundStore` 接口 + 同一套 `Service`，适配 TokenHub 现有 DB 生命周期 |

按此设计可直接在融合架构中落地：单机 SQLite 出活、商用切 PG，Redis 只增强体验与性能，不碰资金真相。
