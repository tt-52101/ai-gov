# 模型路由策略动态矩阵：融合设计与实现方案

面向 TokenHub 底座、吸收 AxonHub 多维评分思想，落实 PRD 中的**可插拔策略矩阵**（启停、组合、非固化四层），并与价格帽、ModelGrant、账户锁定正交。

---

## 1. 目标与边界

### 1.1 目标

| 能力 | 说明 |
|------|------|
| 动态矩阵 | 策略可注册、按档案启用/禁用、可加权或优先级链组合 |
| 融合 | 复用 TokenHub 候选构建/健康/亲和；吸收 AxonHub 式多维打分 |
| 正交 | 不改 `account_id`；先 ModelGrant、价格帽，再跑矩阵 |
| 可观测 | 记录过滤原因与得分，关联 `request_id` |
| 可灰度 | 档案 shadow、单策略开关 |

### 1.2 非目标（本期）

- 用路由结果改写扣费账户  
- 把上游 HTTP 失败自动「记到别的账本」  
- 用 Redis 存权威路由配置（配置仍在 SQL；Redis 仅可缓存档案）

---

## 2. 管道位置（融合数据面）

```text
Auth(Key→account_id 锁定)
  → SecurityHooks
  → ModelGrant          // 模型是否允许
  → BuildCandidates     // TokenHub：渠道×上游模型列表
  → PriceCapFilter      // δ 价格合格集（P0）
  → StrategyMatrix      // 本方案：Filter + Score + Select
  → Adapter 调用
  → （失败可按档案重试下一候选）
  → Settle
```

**硬顺序：** 合规/模型/价格不合格者**不得**进入打分；矩阵不能把已剔除项「加回来」。

## 3. 核心抽象

### 3.1 候选

```go
type Candidate struct {
    ChannelID   int64
    ModelID     string   // 上游或绑定模型
    LogicalModel string  // 请求逻辑模型
    Priority    int      // 配置主备分组
    Weight      float64
    Labels      map[string]string // region, internal_only, ...
    // 运行时填充
    Health      HealthState // up|degraded|down
    EstSell     decimal.Decimal
    EstCost     decimal.Decimal
    LatencyEWMA time.Duration
    ErrorRate   float64
    Score       float64
    Eliminated  bool
    ElimReason  string // price_cap|compliance|health|strategy_id|...
}
```

### 3.2 策略接口

```go
type Phase int
const (
    PhaseFilter Phase = iota // 只剔除
    PhaseScore               // 只打分
    PhaseBoth
)

type Strategy interface {
    ID() string
    Phase() Phase
    // Filter: 置 Eliminated
    Filter(ctx context.Context, in *MatrixInput, cs []Candidate) []Candidate
    // Score: 写 Score 增量或绝对分（由档案约定）
    Score(ctx context.Context, in *MatrixInput, cs []Candidate) []Candidate
}

type MatrixInput struct {
    RequestID    string
    LogicalModel string
    AccountID    int64    // 只读，禁止策略修改扣费
    Stream       bool
    Profile      *Profile
    Now          time.Time
}
```

### 3.3 档案 Profile

```go
type Profile struct {
    ID           string
    Mode         string   // "priority_chain" | "weighted_score"
    Strategies   []StrategyBinding
    Delta        float64  // 价格上浮，0~0.20
    MaxAttempts  int
    Shadow       bool     // true: 只记日志，实际仍用 baseline 档案
}

type StrategyBinding struct {
    StrategyID string
    Enabled    bool
    Weight     float64          // weighted_score 模式
    Config     map[string]any   // 策略私有配置
}
```

存储：SQL 表 `route_profiles`（`config JSONB`），与 TokenHub 现有路由配置可并存，逐步迁移。

## 4. 策略矩阵（实现清单）

| ID | 阶段 | 行为摘要 | 默认可关 |
|----|------|----------|----------|
| S-COMPLIANCE | Filter | INTERNAL_ONLY 剔除外网渠道 | **硬：受限主体不可关** |
| S-HEALTH | Filter/Score | down 剔除；degraded 降权 | 可 |
| S-PRI | Filter/Score | 只保留当前优先级组或按组排序 | 可 |
| S-WEIGHT | Score | 按配置 weight 加权 | 可 |
| S-COST | Score | EstSell/EstCost 越低分越高 | 可 |
| S-LATENCY | Score | EWMA 延迟越低分越高 | 可 |
| S-ERROR | Score | 错误率惩罚 | 可 |
| S-RATE | Filter/Score | 近限流则剔除或降权 | 可 |
| S-AFFINITY | Score/提升 | 同 session 命中渠道加分或置顶 | 可 |
| S-TAG | Filter/Score | 按请求 Tag 匹配 labels | 可 |
| S-CACHE | Filter | 仅作最后一组兜底候选 | 可 |

**S-COMPLIANCE** 在引擎内强制：若请求主体网络策略为 INTERNAL_ONLY，即使档案关闭也执行。

## 5. 组合模式

### 5.1 priority_chain（类 TokenHub 主备）

```text
候选按 Priority 分组 (0,1,2...)
从高组开始：
  组内 Filter → Score → 排序取 Top
  调用失败则同组下一候选；组耗尽进入下一 Priority
```

适合「四层降级」预设档案 `simple-failover`。

### 5.2 weighted_score（类 AxonHub 多维）

```text
对未剔除候选：
  score = Σ (binding.Weight * normalize(strategy_score_i))
排序取 MaxAttempts 个依次尝试
```

归一化：各策略输出建议落在 0～1，避免量纲吞噬。

### 5.3 档案示例


## 6. 引擎执行伪代码

```go
func (e *Engine) Select(ctx context.Context, in *MatrixInput, raw []Candidate) (ordered []Candidate, decision Decision, err error) {
    p := in.Profile
    cs := clone(raw)

    // 0) 价格帽已在上游做完；此处断言无超δ项
    // 1) 强制合规
    cs = e.mustCompliance.Filter(ctx, in, cs)

    // 2) 按档案顺序 Filter
    for _, b := range p.Strategies {
        if !b.Enabled || b.StrategyID == "S-COMPLIANCE" { continue }
        st := e.reg.Get(b.StrategyID)
        if st.Phase() == PhaseFilter || st.Phase() == PhaseBoth {
            cs = st.Filter(ctx, in, withConfig(ctx, b.Config))
        }
    }

    alive := notEliminated(cs)
    if len(alive) == 0 {
        return nil, decision, errNoRoute // NO_ROUTE_AVAILABLE / PRICE_CAP 已在上游
    }

    // 3) Score
    switch p.Mode {
    case "priority_chain":
        ordered = e.priorityChain(ctx, in, alive)
    default:
        for _, b := range p.Strategies {
            if !b.Enabled { continue }
            st := e.reg.Get(b.StrategyID)
            if st.Phase() == PhaseScore || st.Phase() == PhaseBoth {
                alive = st.Score(ctx, in, alive)
            }
        }
        ordered = sortByScoreDesc(alive)
    }

    decision = buildDecision(in.RequestID, cs, ordered, p)
    if p.Shadow {
        // 实际选用 baselineProfile 的结果，decision 仍写 shadow 对比
        ordered = e.Select(ctx, withProfile(in, baseline), raw)
    }
    return ordered, decision, nil
}
```

## 7. 与 TokenHub / AxonHub 融合映射

| 能力来源 | 融合方式 |
|----------|----------|
| TokenHub 渠道列表、priority、weight、affinity、probe | `BuildCandidates` 填 Candidate 字段；S-PRI/S-WEIGHT/S-AFFINITY/S-HEALTH 读这些字段 |
| TokenHub 现有路由配置 | 迁移为 Profile 或运行时适配器「旧配置 → simple-failover 档案」 |
| AxonHub 多维负载 | S-COST/S-LATENCY/S-ERROR/S-RATE 的 Score 实现与归一化 |
| 本产品价格帽/双轨 | PriceCapFilter + EstSell 来自 pricing 包 |
| 本产品资金 | MatrixInput.AccountID 只读；禁止 Strategy 写账户 |

## 12. 实现分期

| 迭代 | 交付 |
|------|------|
| R0 | Engine 骨架 + PriceCap 后接入 + 透传 TokenHub 原顺序（单策略 NoopPass） |
| R1 | S-COMPLIANCE、S-HEALTH、S-PRI、S-WEIGHT + priority_chain + simple-failover 档案 |
| R2 | S-COST、S-LATENCY、S-ERROR、weighted_score + ha-cost 档案 |
| R3 | S-AFFINITY、S-RATE、S-TAG、Shadow、决策日志 UI |
| R4 | 与 Party 档案绑定、指标大盘 |

R0 可与财务 M1 并行挂接；R1～R2 对应总计划 M2。

## 13. 测试清单

| 用例 | 期望 |
|------|------|
| 仅外网候选 + INTERNAL_ONLY | 全剔除，ROUTE_COMPLIANCE_BLOCKED / NO_ROUTE |
| 贵候选超 δ | 进不了矩阵（价格层） |
| 禁用 S-COST | 排序不依赖价格分 |
| ha-cost vs simple-failover | 同候选集顺序可差异化 |
| Shadow | 实际路径稳定，日志有对比 |
| 策略尝试改 account | 编译/接口层无法改（只读 Input） |
| 流式首包后失败 | 不切渠道 |
| 全 down | NO_ROUTE_AVAILABLE |

## 14. 与守恒/资金的关系（再次钉死）

```text
矩阵输出 = 渠道与模型尝试序
扣费账户 = Auth 阶段锁定
成功/失败计费 = Freeze/Settle/Orphan（资金模块）
```

路由失败不扣卖价；上游成功但结算失败走资金收口清单，不由矩阵「换账户重扣」。

## 15. 小结

| 项 | 方案 |
|----|------|
| 形态 | 可插拔 Strategy + Profile（chain / weighted） |
| 融合 | TokenHub 候选与健康 + AxonHub 多维分 + 本产品价格帽/合规 |
| 动态 | 档案级启停、权重、δ、Shadow |
| 实现 | `internal/routing` 引擎与 strategies 包，SQL 存档案 |
| 落地顺序 | R0 挂钩 → R1 主备链 → R2 加权成本 → R3 可观测与亲和 |

按本方案可在融合架构中复用并渐进替换固化四层，同时满足商业灵活调度与资金正交硬约束。
