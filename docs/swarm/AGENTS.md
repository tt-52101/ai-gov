# 蜂群功能验收作战计划 — 6 大专家蜂群矩阵

**基线：** PRD v3.2.0 §13 验收标准 + §7.7 验收红线 + AGENTS.md §7 蜂群作战准则

---

## 作战准则（不可违反）

| # | 铁律 | 说明 |
|---|------|------|
| 1 | **事实驱动** | 每个结论必须附 PRD 条款引用 + 代码/日志/截图证据，禁止主观判断 |
| 2 | **独立作战** | 各蜂群互不通信，禁止串通、互相遮掩、统一口径 |
| 3 | **第一性原理** | 从 PRD 公理出发推导验收结论，不依赖任何人的口头承诺 |
| 4 | **红线即死刑** | §7.7 的 13 条红线任一条触发 = 验收不通过，立即阻断 |
| 5 | **存证落盘** | 每个蜂群的验收报告写入 `docs/delivery/acceptance/<蜂群名>/` |

## 六大蜂群矩阵

### 蜂群 1：QA 功能验收蜂群（4 Agent）

**验收范围：** PRD §13.1 功能验收（26 场景）

| Agent | 验收域 | 核心场景 | 证据要求 |
|-------|--------|---------|---------|
| QA-1 | 资金治理 | 划拨守恒/冻结TTL/结算/清算5阶段/幂等/预算帽分码/告警不阻断 | 流水记录截图 + SQL 校验 + API 响应 |
| QA-2 | 接入+计价+路由 | 统一接入≥6类/双轨item分项/缓存折扣/固定摊销/δ价格帽/12策略启停 | 调用日志 + cost/sell 对比 + 策略管道日志 |
| QA-3 | 安全治理 | ABAC四轴越权/DENY优先/UI权限投影/审计不可篡改/密钥安全/禁人禁Key | ABAC评估日志 + 审计快照 + API 403响应 |
| QA-4 | 模型+调度+追踪 | ModelGrant deny优先+级联/双层预算/调度不改账户/全链路追踪/INTERNAL_ONLY | ModelGrant决策日志 + request_id全链路 |

**红线检查（§7.7，每个 QA Agent 独立执行）：**
- [ ] 无流水改余额
- [ ] 划拨无通道
- [ ] Key 无 account 调用
- [ ] 调度改扣费账户
- [ ] 先调后欠费
- [ ] Leader 无 Grant 全平台权限
- [ ] iam 建 Key 绑无权账户
- [ ] 预算帽/余额不足同错误码
- [ ] ModelGrant deny 后仍可调
- [ ] 前端隐藏按钮但 API 未校验
- [ ] UI 按钮对应动作不存在
- [ ] 审计日志可 UPDATE/DELETE
- [ ] INTERNAL_ONLY 产生外网流量

**验收范围：** PRD §13.3 财务演示脚本 + §13.4 安全治理演示脚本 + §0 用户旅程

| Agent | 验收内容 | 通过标准 |
|-------|---------|---------|
| PRD-1 | 财务闭环演示（§13.3 全流程） | 配置预算+加价 → 划拨 → Key调用 → 核对sell/cost/流水 → 双层预算帽分码 → 清算回流 → 组织合并 → 幂等划拨 —— 全程可重复、数据一致 |
| PRD-2 | 安全治理演示（§13.4 全流程）+ 3 条用户旅程（§0 附录） | ABAC策略评估→UI权限投影→审计不可篡改→ModelGrant deny → 财务人员旅程→部门Leader旅程→普通员工旅程 |

### 蜂群 3：红蓝对抗安全蜂群（3 Agent）

**验收范围：** PRD §13.2 非功能验收第 3 项（渗透测试）+ §7 安全治理体系 + 25 条守恒定理

| Agent | 攻击面 | 攻击手法 | 预期结果 |
|-------|--------|---------|---------|
| RED-1 | 权限提升 | IDOR（修改 URL 中 resource_id 访问他人数据）、ABAC 绕过（直接调用 API 跳过中间件）、JWT/API Key 伪造 | 全部返回 403 AUTHZ_DENIED 或 401 |
| RED-2 | 资金攻击 | 重复划拨（无幂等键）、并发划拨（竞态条件）、负金额划拨、自划拨、绕过通道直接 SQL 改余额 | 守恒定理全部守住；重复划拨被幂等拦截；并发安全 |
| RED-3 | 数据泄露 | INTERNAL_ONLY 用户请求外网模型、密钥明文泄漏（日志/API响应）、审计日志篡改 | INTERNAL_ONLY→阻断；密钥不落日志；审计不可删改 |

### 蜂群 5：顶级技术研发蜂群（3 Agent）

**验收范围：** AGENTS.md §6 代码质量铁律 + 架构合规

| Agent | 检查范围 | 检查项 |
|-------|---------|--------|
| TECH-1 | 代码质量 | 中文注释覆盖率 100%；文件≤500行；函数≤80行；无过度设计（7种禁止模式）；GORM 注入而非裸 SQL |

| TECH-3 | 测试覆盖 + 编译 | 120 测试全部 PASS；go build/vet 零告警；资金测试含守恒/冻结/幂等验证；Mock 仅用于外部边界 |

## 交付存证规范

每个 Agent 完成后输出验收报告至：

```
docs/delivery/acceptance/
├── qa/                    ← 蜂群 1 报告
│   ├── QA-1-资金治理.md
│   ├── QA-2-接入计价路由.md
│   ├── QA-3-安全治理.md
│   └── QA-4-模型调度追踪.md
├── product/               ← 蜂群 2 报告
│   ├── PRD-1-财务演示.md
│   └── PRD-2-安全演示+旅程.md
├── red-blue/              ← 蜂群 3 报告
│   ├── RED-1-权限提升.md
│   ├── RED-2-资金攻击.md
│   └── RED-3-数据泄露.md
├── ued/                   ← 蜂群 4 报告
│   ├── UX-1-角色导航+危险确认.md
│   └── UX-2-全页面体验.md
├── tech/                  ← 蜂群 5 报告
│   ├── TECH-1-代码质量.md
│   ├── TECH-2-架构合规.md
│   └── TECH-3-测试+编译.md
└── data/                  ← 蜂群 6 报告
    ├── DATA-1-财务守恒.md
    └── DATA-2-DDL+审计链.md
```

**报告格式强制要求：**
```markdown
# <Agent名称> 验收报告

## 检查项清单
| # | PRD 引用 | 检查项 | 结果 | 证据 |
|---|---------|--------|------|------|
| 1 | §13.1 行1126 | 统一接入≥5类公有+1私有化 | ✅/❌ | [截图/日志/代码引用] |

## 红线触发情况
（如触发任一条，标注"验收阻断"）

## 验收结论
✅ 通过 / ❌ 不通过（附 PRD 引用）
```
