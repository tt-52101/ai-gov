#### 缺失的外键约束 (设计发现)

| 表名 | 列名 | 建议引用 | 影响 |

| `api_keys` | `owner_user_id` | `users(id)` | 允许插入不存在的用户 ID |

## 五、总结

### 测试结果总览

| 类别 | 总数 | 通过 | 失败 | 通过率 |
|------|------|------|------|--------|
| 建表 | 40 | 40 | 0 | 100% |
| 显式索引创建 | 102 | 102 | 0 | 100% |
| 外键约束验证 | 11 | 11 | 0 | 100% |

| 索引存在性抽查 | 57 | 57 | 0 | 100% |
| 账户余额/预算帽 | 8 | 8 | 0 | 100% |
| 种子数据行数 | 12 表有数据 | -- | -- | 符合预期 |

### 关键发现

1. **40 表 DDL 全部可行**: 在 SQLite 环境下全部建表成功，DDL 结构严谨，列类型、默认值、约束定义均符合设计预期。

2. **6 处缺失的外键约束**: `api_keys.owner_user_id`, `api_keys.account_id`, `party_edges.src_party_id`, `party_edges.dst_party_id`, `party_members.party_id`, `party_members.user_id` 这 6 个 NOT NULL 列在 DDL 中未声明 REFERENCES 约束。建议在生产 PostgreSQL 环境中补充，以确保引用完整性由数据库层面强制执行。

3. **种子数据覆盖完整**: 涵盖了 PRD v3.2 的核心治理实体链路: 用户 -> 角色 -> 权限 -> ABAC 策略，以及 组织 -> 账户 -> 预算帽 -> API Key -> 模型授权 -> 双轨价目。

4. **双轨定价模型可用**: `model_prices.price_json` 的 JSON 结构通过 SQLite TEXT 列存储，支持 cost/sell 双轨模式 (usage_per_unit)，与 PRD 4.4 定义一致。

5. **ABAC 安全治理表结构正确**: 9 张新增表 (sys_action_catalogs 到 sys_ui_action_bindings) 的 FK 级联行为符合设计 (CASCADE 用于权限关联, SET NULL 用于 UI 引用)。

6. **PostgreSQL 专有函数未测试**: `evaluate_access()`, `evaluate_access_via_roles()`, `anchor_audit_chain()` 三个 plpgsql 存储过程在 SQLite 中无法创建，留待 PostgreSQL 集成测试阶段验证。
