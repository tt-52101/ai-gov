**代码位置**: 分散在多处

**代码路径溯源**:

限流相关错误码散布在代码中：
1. `types.go:57`: `ErrRateLimitExceeded = NewHTTPError(429, "rate_limit_exceeded", "Rate limit exceeded")`
2. `store.go:2180`: InFlightLease 并发控制超限 → `ErrRateLimitExceeded`
3. `store.go:2291-2296`: Provider Resource RPM/TPM 超限 → `"provider_resource_rpm_exceeded"` / `"provider_resource_tpm_exceeded"`
4. `routing/strategies/rate.go:41-42`: S-RATE 策略——降权而非阻断（-8 分）

**验证结果**: 缺口 -- 无统一 RATE_LIMITED 错误码
- **实际错误码**: `rate_limit_exceeded`（与 PRD 期望的 `RATE_LIMITED` 不一致）
- 限流有两层机制：
  - InFlightLease（飞行中并发控制）：超限返回 `rate_limit_exceeded`
  - ProviderResourceBucket（RPM/TPM 桶）：超限返回 `provider_resource_rpm_exceeded` / `provider_resource_tpm_exceeded`
- S-RATE 策略仅在路由评分阶段降权，不做硬阻断
- **缺口**: 
  - 缺少网关层全局限流（PRD 期望的独立 RATE_LIMITED）
  - 错误码命名不一致（`rate_limit_exceeded` vs `RATE_LIMITED`）
  - Provider 级限流返回的是 `provider_resource_rpm_exceeded`，用户不可见
- **建议**: 在网关入口增加全局限流中间件，统一返回 `RATE_LIMITED`

### 5.7 非 UUID v4 格式的 Idempotency-Key

**预期**: 应拒绝
**代码位置**: `idempotency/middleware.go:107-109` (ValidateKey), `idempotency/middleware.go:124-159` (isValidUUIDv4)

**验证结果**: 正确
- `isValidUUIDv4()` 验证: 36 字符 + 连字符位置 + 版本半字节 '4' + 变体半字节 [89abAB] + 十六进制校验
- 验证失败 → 400 `IDEMPOTENCY_KEY_INVALID`
- 注意：该验证在 Middleware 层执行，但代码注释（L42-43）提到"非 UUID 值带警告被接受但不拒绝"——而实际 ValidateKey 拒绝非 UUID 值。注释与代码不一致
