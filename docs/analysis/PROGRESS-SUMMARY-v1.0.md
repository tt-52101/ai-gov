## 5. 风险与决策点

### 5.1 风险

1. **无集成测试环境风险（高）：** 当前所有测试均为单元测试（242+ PASS）。无端到端集成测试，无法验证真实数据库行为（如触发器 `trg_append_only`、存储过程 `anchor_audit_chain`）。
2. **前端联调风险（高）：** 前端 8 模块实现了 mock 数据，但从未与真实后端 API 联调。API spec 与前端实现之间可能存在偏差。
3. **国产兼容风险（中）：** PostgreSQL 方言与 OceanBase/TiDB 之间存在差异（如 GORM 的 `clause.Locking`、窗口函数 `LEAD`），未经过国产数据库验证。
4. **性能风险（中）：** 无性能基线数据。14 步管线在无缓存、无连接池调优下的端到端延迟完全未知。

### 5.2 决策点

1. **阶段 D/E 的资源分配：** 是继续用蜂群并行模式（8 Agent）还是精简团队（4 Agent）？并行模式在 bug fix 场景效率高，但在新功能开发（阶段 D）需要更多上下文协调。建议 D 阶段用 4 Agent 串行核心路径，E 阶段用 3 Agent 并行验证。
2. **集成测试环境就绪时间：** 需要决策是使用 Docker Compose 本地 PostgreSQL 还是申请公司内部测试环境。建议先用 Docker Compose 快速验证，国产环境留到 E-1。
3. **需求丢失清单 L-01~L-17 的处理策略：** 建议不在 GA 前强行关闭全部 17 项。GA 交付以功能完整+安全合规为界，L-01（对外售卖）、L-09（模型预判器）、L-16（增强目录）等远期项纳入 post-GA roadmap。
