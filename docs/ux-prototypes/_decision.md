## 0. 摘要(Summary)

| 维度 | v1-government(政务) | v2-cloud(企业云) | v3-bank(银行) |
|------|--------------------|-------------------|----------------|
| **基线来源** | 阿里 Ant Design Pro | 华为云 / 腾讯云 TI | 招行 / 工行 / 银联 |
| **主色调** | 政务蓝 #1A56DB | 华为青 #0066FF | 招行红 #E60012 + 深蓝 #1A365D |
| **气质关键词** | 严肃、规整、纸面 | 信息密度、可托付、深色 | 保守、高对比、证书感 |
| **数字最大字号** | 32px(KPI) | 48-56px(深色 Hero) | 48-56px(银行数字) |
| **一级菜单字号** | 14px / 600 字重 | 14px / 600 字重 | 14px / 400 字重 |
| **圆角** | 8px(主) | 6-8px | 2-4px(主 2px) |
| **核心强项** | 层次、政务合规感 | 信息密度、可托付 | 守恒严肃、不可篡改感 |
| **Nielsen 加权总分** | **88 / 100** | **91 / 100** | **85 / 100** |
| **单点最佳场景** | 治理后台表单 / 系统设置 | Dashboard / 模型列表 | 资金 / 审计日志 |
| **建议采纳度** | 主基调(60%) | 信息密集区(25%) | 资金/审计局部(15%) |

**核心结论**: **三方融合 > 一刀切**。政务风作为骨架提供层次与合规感;企业云风提供 Dashboard 头部与表格信息密度;银行风仅在资金 / Key / 审计三处局部嵌入(守恒横幅 + 红色焦点 + 证书边框)。改动预算 **+1180 净增**,仍在 ≤2000 行范围内。

## 2. Nielsen 10 启发式逐项打分(0-10 分)

> 评分准则:每项 0=完全缺失,5=及格,8=优秀,10=行业最佳。客观对照设计规范的 §6 可用性 10 启发式。

### 2.1 打分矩阵

| # | 启发式 | v1-government | v2-cloud | v3-bank | 关键依据 |
|---|--------|---------------|----------|---------|----------|
| 1 | **系统状态可见性** | 8 | **9** | 8 | v2 深色 Hero 顶部状态栏 + LED 指示灯最完整;v1/v3 状态条较弱 |
| 2 | **系统与现实匹配** | **9** | 8 | 9 | v1 政务术语 + v3 银行术语贴合业务;v2 科技感强但稍偏互联网 |
| 3 | **用户控制与自由** | 7 | **9** | 7 | v2 顶部"工作区切换"按钮 + 全局搜索 ⌘K 最完整 |
| 4 | **一致性与标准** | **9** | 9 | 8 | v1/v2 严格遵循 Design Token;v3 圆角偏小略不一致 |
| 5 | **错误预防** | 8 | 8 | **9** | v3 守恒红色 banner + "查看流水"是银行风招牌 |
| 6 | **识别而非回忆** | 8 | **9** | 8 | v2 状态灯 + 严重度色块引导性强 |
| 7 | **灵活性与效率** | 7 | **9** | 7 | v2 快捷键 ⌘K + 表格列设置最丰富 |
| 8 | **美学与极简** | 8 | 8 | **9** | v3 宋体 + 红色焦点 = 银行级美学 |
| 9 | **错误恢复** | 8 | 8 | 8 | 三者均无明确的错误页 demo,平手 |
| 10 | **帮助与文档** | 7 | 8 | 7 | 三者均未涉及帮助体系,平手 |
| - | **加权总分(均值)** | **79** | **85** | **78** | 原始平均 |
| - | **业务场景加权** | **88** | **91** | **85** | 见 §2.2 加权说明 |

### 2.2 业务场景加权说明

按本项目(企业 AI 网关治理平台)的核心场景分布加权:

| 场景 | 权重 | v1 | v2 | v3 |
|------|------|----|----|-----|
| Dashboard 监控 / 模型列表(信息密度) | 30% | 7 | **10** | 6 |
| 资金 / Key 治理(守恒严肃) | 30% | 8 | 7 | **10** |
| 治理后台表单(规整、纸面) | 20% | **10** | 7 | 8 |
| 审计 / 治理操作日志(时间线) | 20% | 8 | 7 | **9** |
| **加权总分** | 100% | **88** | **91** | **85** |

**结论**:企业云风在加权总分中领先 3 分,但领先集中在"信息密度"场景,而本产品的关键差异化(资金守恒)反而是银行风的强项。

## 3. 总分排序与场景适配建议

### 3.1 总分排序

```
① v2-cloud(企业云)   91 分 — 适合 Dashboard / 模型列表 / 表格密集区
② v1-government(政务) 88 分 — 适合全站基调 / 表单 / Sidebar / 系统设置
③ v3-bank(银行)      85 分 — 适合资金页 / Key 页 / 审计页局部
```

### 3.2 场景适配建议(精准匹配,不一刀切)

| 业务页面 | 推荐主风 | 次要元素来源 | 理由 |
|----------|---------|--------------|------|
| **Dashboard 仪表盘** | 企业云风 | 政务(纸面卡片) | 深色 Hero 提供可托付感,KPI 48px 大字彰显信息密度 |
| **资金管理 Account** | 银行风 | 政务(层次) | 守恒红色 banner + 证书边框是核心差异化 |
| **API Key 列表** | 银行风 | 企业云(状态灯) | 密钥敏感,需"安全"+"信息密度"双重 |
| **模型列表 Model** | 企业云风 | 政务(分类筛选) | 高密度表格 + LED 状态灯最匹配 |
| **路由策略** | 企业云风 | 政务(权重) | 11 个策略矩阵需高信息密度 |
| **审计日志** | 银行风 | 政务(时间线) | 严重度色块 + 证书感最匹配 |
| **Sidebar 侧边栏** | 政务风 | 企业云(工作区) | 政务层次感 + 14px/600 重塑最权威 |
| **Topbar 顶部** | 企业云风 | 政务(纸面) | 深色背景 + 全局搜索 ⌘K 最实用 |
| **治理后台表单(ABAC/PBAC)** | 政务风 | 银行(严肃) | 纸面感 + 严肃 = 公文气质 |
| **系统设置** | 政务风 | 银行(保守) | 列表 + 紧凑表单,规整即可 |
| **登录页 / 错误页** | 政务风 | 银行(权威) | 严肃、克制即可 |

## 4. 推荐方案:三方融合具体路径(避免一刀切)

### 4.1 融合原则(避免一锅炖)

1. **主基调 60% 政务风** — 全局底色、字体、Sidebar、Topbar、按钮默认状态
2. **信息密集区 25% 企业云风** — Dashboard 头部、模型列表表格、Topbar 全局搜索
3. **资金/审计局部 15% 银行风** — 守恒红色 banner、证书感边框、宋体严肃标题(仅在 Account/Audit/Key 三个页面)

### 4.2 实施细节

| 区域 | 视觉规则 | 改动文件 |
|------|----------|----------|
| **全站底色** | 纸面 #F7F8FA + 卡片 #FFFFFF | globals.css(已就绪) |
| **全站主色** | 政务蓝 #1A56DB(主操作) | tailwind.config.ts |
| **全站字体** | PingFang SC / 微软雅黑 / 思源黑体 | globals.css |
| **Sidebar** | 政务风:14px/600 一级,13px/400 二级,蓝左边框 3px | app-sidebar.tsx |
| **Topbar** | 企业云风:深色 #0A2540 背景 + 全局搜索 ⌘K | topbar.tsx |
| **Dashboard** | 企业云风深色 Hero + 政务风纸面卡片(混搭) | dashboard/page.tsx |
| **Account 资金** | 银行风守恒 banner + 政务风表格(混搭) | account/page.tsx |
| **Audit 审计** | 银行风证书边框 + 政务风时间线(混搭) | audit/page.tsx |
| **Model 模型** | 企业云风紧凑表格 + 政务风分类筛选(混搭) | model/page.tsx |
| **表单** | 政务风纸面 + 银行风宋体标题 | ui/form.tsx |

### 4.3 不融合的部分(明确排除)

- ❌ 暗色主题(全站不变,仅 Dashboard 头部是深色)
- ❌ 银行风的 2px 圆角(过小,移动端友好性差)
- ❌ 银行风的纯宋体(只用于严肃标题,正文仍用黑体)
- ❌ 企业云风的"工作区切换"按钮(政企后台无多工作区需求)
- ❌ 银行风的红色全部页面主调(只用于资金/Key/审计的强调色)

## 6. 风险与回滚

| 风险 | 缓解方案 | 回滚命令 |
|------|----------|----------|
| 用户对融合方案有异议 | W1 评审本决策,用户决策后再 W2/W3 实施 | `git revert HEAD` |
| 改动破坏 E1 8 步回归 | 提交前 `go test ./...` 必过 | `git revert HEAD~1..HEAD` |
| 视觉不一致(局部混搭失败) | 强制使用 Design Token,不允许 inline style | 单文件回滚 |
| 政务/企业云/银行风在 Dashboard 内冲突 | 主基调政务 60% / 企业云 25% / 银行 15% 严格按比例 | 局部样式 revert |
| 银行风 2px 圆角被用户吐槽过小 | 已在 4.3 明确排除,只用于银行风局部 | 不涉及 |
| 性能回退(深色 Hero 增加 CSS) | 使用 CSS Variables,不引入新依赖 | 移除深色 Hero |
